# T027: Antigravity and Codex adapters; retire the Gemini CLI adapter

## Goal
Google ended Gemini CLI's Google-account sign-in for individuals on 2026-06-18 (the CLI now answers `UNSUPPORTED_CLIENT` and points at Antigravity), so the owner's subscription can no longer drive orch's validator. When this task is done, `src/adapters/antigravity.ts` (Antigravity CLI, `agy`) and `src/adapters/codex.ts` (OpenAI Codex CLI) exist, are registered in `src/adapters/index.ts` and shipped as default adapters `antigravity` and `codex` in `src/config.ts`; `src/adapters/gemini.ts` and the `gemini` default are gone, with a clear upgrade error for a `server.json` that still names them; the Docker image installs `agy` and `@openai/codex` instead of `@google/gemini-cli`; and each new adapter has completed one real task in the image on a subscription login, with its recorded stream as a unit fixture. Decision record 0024 explains the change; 0007 (adapters per CLI) stands.

## Acceptance criteria
- Given adapter `{type: "antigravity", command: "agy", extraArgs: ["--dangerously-skip-permissions"]}`, When `launch` runs with model `m` and no session, Then args are `--output-format stream-json --input-format stream-json --dangerously-skip-permissions --model m` and stdin is one line `{"event":"user","message":{"content":<prompt>}}`; with `resumeSessionId: "c1"` the args also contain `--conversation c1`.
- Given the recorded Antigravity stream fixture in `test/fixtures/adapters/antigravity.jsonl`, When each line goes through `parseLine`, Then the first event is `info` with `subtype: "init"` and `session_id` equal to the `conversation_id`; every `tool` step yields one `tool` event (name, summarized parameters) and one `agent` tool_result (output, `is_error` from `tool_info.error`); `agent_response` deltas of one step become one `text` event; after `finish`, `finalText` is `result.response`, `isError` is false, `costUsd` is null; a `result` with `status: "ERROR"` sets `isError` and yields an `error` event with `result.error`.
- Given adapter `{type: "codex", command: "codex", extraArgs: ["--dangerously-bypass-approvals-and-sandbox"]}`, When `launch` runs with model `m`, Then args are `exec --json --dangerously-bypass-approvals-and-sandbox --model m -` and stdin is the prompt; with `resumeSessionId: "t1"` the args start `exec resume t1` (prompt placement per the contract's verified result).
- Given the recorded Codex fixture `test/fixtures/adapters/codex.jsonl`, When parsed, Then `thread.started` sets `sessionId`, each `command_execution` item yields a `tool` event on `item.started` and an `agent` tool_result on `item.completed`, the last `agent_message` text is `finalText`, `turn.completed.usage` appears in an `info` event, `costUsd` is null, and a `turn.failed` or `error` line sets `isError` with an `error` event.
- Given `agents.adapters.x` with `type: "gemini"` in a server config, When `loadServerConfig` runs, Then it throws `<file>: agents.adapters.x has type "gemini", retired in T027 (decision 0024); use type "antigravity" (command agy) or "codex", or remove it and point roles at claude`.
- Given `npm run check`, Then the vendor regex also matches `antigravity|agy|codex|openai`, the `src/config.ts` allowlist covers only the new defaults, and no file outside `src/adapters/` names a vendor otherwise; `src/adapters/gemini.ts` does not exist.
- Given `npm run test:e2e` with the planner on `codex` and the validator on `antigravity` (worker stays `claude`), Then the run completes planning, work, validation and resume; events show `validator started (antigravity)` and init events with models `fake-antigravity` and `fake-codex`; the run row's own cost stays n/a and the project total equals Claude calls × $0.01 (TASK-17 assertions, re-targeted).
- Given `docker compose build`, Then the image has `agy --version` and `codex --version` and no `gemini` binary; compose defines volumes for `/home/orch/.gemini` (Antigravity settings) and `/home/orch/.codex`, and passes `GEMINI_API_KEY`, `CODEX_API_KEY` and `OPENAI_API_KEY` through from `.env`.
- Manual: one real task per new adapter runs to a PASS verdict in the Docker image using a subscription login (Codex via `codex login --device-auth`; Antigravity via the sign-in the contract describes, or the documented fallback if the keyring blocks it). The PR records the exact login steps, the problems met, and the stream lines that became the fixtures.

- Prompt tuning for the new agents beyond what the real runs require.
